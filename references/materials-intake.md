# 资料接收与符号忠实规则

## 启动询问

启动统一按 `user-experience.md` 合并关键问题，下例是表达参考，不与其他文件的启动问题重复询问。

新项目在读取现有文件后，主动询问尚未明确的资料需求。可以合并为：

> 你是否有PPT、教材、课程大纲、教师笔记或参考讲义？如果提供，我会以这些资料为依据，严格沿用其中的字母、符号、下标、术语和公式约定。是否允许我补充互联网资料，还是只使用你提供的内容？

使用可接收附件的普通聊天询问资料；仅支持文字的询问工具可用于询问有无资料和来源偏好，不用于要求上传附件。用户说明稍后提供时，可以先整理项目和模板；必须依据资料才能完成的正文等待资料到齐，不以猜测填补。

记录来源模式：仅用户资料、允许指定来源、允许补充可靠公开来源。明确的既有授权继续有效，不重复询问；没有回答不视为网络搜集授权。有资料时尽早告知“严格沿用资料记号”，不要直到交付才提到。

## 读取与整理

- 先列出实际收到的文件及其类型、课程范围和版本，不把文件名当作已读取正文。
- PPT按幻灯片顺序读取，PDF按页码定位；公式、图表、扫描件和手写内容须视觉核对，不能仅依靠纯文本提取。
- 建立资料到章节的对应关系，记录重要定义、公式及符号的文件名、幻灯片号或页码。项目需要长期维护时，在 `资料索引.md` 中保存对应关系与歧义。
- 资料决定范围、定义和约定，正文按知识依赖补足必要解释和中间步骤。用户要求严格按原顺序或仅限原内容时，遵从该边界。
- 原文件只读，不修改、移动或重命名。读取工具不可用时说明实际限制，不声称已读取。

使用 `assets/material-receipt.md` 的表格保存实际读取、符号映射和待处理问题，交付一份简短回执。显示关键符号的原页位置或截图，便于用户核对。已解决问题更新原记录；阻塞问题集中询问，不因非阻塞问题暂停其他内容。

## 沿用字母、符号和公式

根据实际资料建立符号表，至少记录原符号、含义、单位或维度及出处。逐项保护：大小写、希腊字母、字体所表达的向量/矩阵含义、上下标、撇号、正负号、坐标方向、单位、定义与公式约定。需要追踪原公式时记录原编号；讲义可另建连续编号，并保留到原编号的映射。

例如：资料使用 `ν` 表示物质的量时，不自行改成 `n`；资料规定吸热、对外做功为正并使用 `Q = ΔE + W` 时，沿用该记号与符号约定。排版转写可以改变公式的书写载体，但不能改变数学含义。

同一字母在不同章节含义不同，章首明确说明，不强行统一。多份资料冲突时列出具体出处并询问采用哪一套；用户指定的主资料优先。明确错误、疑似笔误和模糊字符都须定位说明，不静默修正，也不把明显矛盾无条件写成正确结论。等待答复期间继续处理无争议部分。

为解释新增必要记号时，先检查是否与原资料冲突，并标注为讲义新增辅助记号。不能以“标准写法”或“更常见”为理由替换用户资料中的符号。

## 网络补充

获得授权后，优先选择原始论文、官方文档、权威教材或机构课程。补充资料负责解释或拓展，沿用用户资料中的符号体系；明确注明补充内容及来源，避免让用户误以为其来自原PPT。

用户拒绝网络补充时，按其资料及授权边界写作；无法确定的内容注明待核实，不编造出处或外部事实。若当前环境要求必要的事实核查，说明核查用途与所得结果，不把它当成扩大讲义范围的授权。
